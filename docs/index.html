BUCHILAB / REPEATED-GOAL GAMES Source Method

A winning state is not
a winning policy.

Safe waiting can last forever. Repeated goals need progress, even against an environment that never helps. Follow every nested fixed point, rank and controller policy.

A tiny finite turn-based model. No fairness assumption, model API or real-system guarantee.

1. Choose the repeated-goal game

Winning means visiting a goal state infinitely often, from each possible root. Reaching a goal once is not enough. An environment action that is always available need never be taken.

2. Replay both fixed points

Start outer Z at every state. For each outer candidate, start inner Y empty. Goal states test successors in Z; non-goal states test successors in Y. Controller uses exists; environment uses all. Every inner and outer final unchanged round is included.

3. Inspect a progress-preserving strategy

At a non-goal winning state, use a lower inner rank. At a goal state, reset anywhere in the winning region. Non-goal ranks bound steps to a goal; goal moves reset the rank. This is recurrence, not completion time. These rank-permitted moves give one sufficient policy family, not every winning policy.

Staying inside winning states alone is not enough. The idle self-loop in the first control stays inside the winning region and still loses. A rank-decreasing move restores progress.

4. Audit every positional controller policy

Fix one controller action at every controller state; retain every environment action. A root loses exactly when it can reach a cycle consisting entirely of non-goal states. Find cycles in the non-goal induced graph, not only bottom SCCs of the full graph. An adversarial environment can stay on a cycle even with an exit available.

Every retained edge

Every cyclic non-goal component

5. Replay the full certificate

The native checker independently replays with sets, finds cyclic components using Floyd reachability, and enumerates every joint controller/environment policy. Each deterministic pair is checked by its exact eventual lasso. The generator uses bitmasks and Tarjan SCCs. No solver calls in the checker.

Scope and attribution
One to six states, one to three moves each. Finite, total, deterministic moves, turn-based perfect information. No fairness, clocks, probabilities, simultaneous moves, partial observation, learned abstraction, temporal-logic compiler, runtime enforcement, reward or real-system guarantee. Empty goals lose; every-state goals win. Dead ends are rejected.
Original code and controls using established Buchi-game theory. Not a new algorithm, deployed agent shield or formal proof. The method and source ledger distinguish this model from generalized, stochastic and concurrent games.
